# PR #1 fixes and cleanup

Date: 2026-10-15

Follow-up to the [original review](2026-10-15-pr-1-review.md) of
[PR #1, Integrate Bookish changes](https://github.com/elegantchaos/Application/pull/1).

## Ownership fixes

- Added failing regression tests before implementation. Recovery reproduced an old
  task clearing its replacement's handle, and a cancelled old invocation reporting
  a late error over the replacement. A weak-reference test reproduced a cancelled
  observation retaining its callback owner.
- Startup invocations compare their captured task handle with the engine's current
  handle before clearing ownership or publishing success/error. The captured
  handle is released on completion. Repeated advancement is idempotent, and
  recovery outside an error state leaves active startup untouched.
- ObservationToken owns the value reader and callback. Observation's installed
  closure retains only the token; cancellation clears the token's owned closures
  immediately, including when delivery is already queued. Tests cover callback
  and value-reader release, cancellation from a handler, sequential delivery,
  mutation coalescing, and discarded-token delivery.

## Compatibility and cleanup

- Kept public function signatures, AppEngine requirements, and the public token
  initializers. No additional state is required from conforming engines.
- Preserved fire-and-forget Observation monitoring when callers discard the
  token. Automatic teardown on dropping that token would change existing behavior.
  Explicit cancellation now releases captured resources. NotificationToken keeps
  its existing cancellation-on-destruction behavior. README and API comments
  explain these different lifetimes and Observation's coalescing behavior.
- NotificationToken uses isolated deinitialization and actor-isolated stored
  state instead of nonisolated(unsafe). Added notification filtering,
  cancellation, destruction, and UserDefaults initial-delivery/wiring tests.
- Moved the default shell views and demo types into focused files, documented
  declarations, fixed headers/formatting, and removed unused stored error-phase
  state while preserving DefaultErrorView's initializer signature.
- Removed the empty SettingsTests template and the demo's empty observation task.
  The demo now owns its engine with State, observes ServiceA with a weak ServiceB
  capture, and cancels that observation at teardown. Its manual startup
  continuation is consumed once and handles cancellation by invocation identity.
  View-body mutation counters were removed; custom demo views have previews.
- Observation tests await buffered callback signals instead of Task.yield and
  self-confirming confirmations. Async suites have time limits so a missing
  callback produces a bounded failure.
